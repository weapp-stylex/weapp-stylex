Every adapter re-exports the [`StylexCompilerOptions`](/api/compiler/#api-StylexCompilerOptions) type. Options default to `{}` and therefore the Babel backend. These are build-time imports; application runtime imports remain at `weapp-stylex`. Named/default exports shown below refer to the same function.

## Shared options

| Option | Default | Contract |
| --- | --- | --- |
| `target` | Inferred from host | `weapp | alipay | tt | web`; explicit configuration must match the host. |
| `backend` | `'babel'` | `'auto'` uses the verified SWC subset; `'swc'` rejects unsupported/unavailable inputs. |
| `importSources` | Four official/façade sources | Replaces the list; include the defaults when adding a façade. |
| `babel` | No custom options | Partial official StyleX plugin options, not general Babel configuration. |

`WEAPP_STYLEX_BACKEND` is an example configuration convention, not a library environment API. Set `backend` explicitly. Build enforcement and diagnostics are detailed in the [compiler reference](/api/compiler/).

<a id="api-stylexCompiler"></a>
## stylexCompiler

```ts
stylexCompiler(options: StylexCompilerOptions = {}): WeappCompilerPluginOption
```

Named and default export of `weapp-stylex/weapp-vite` or `@weapp-stylex/weapp-vite`. Returns a native weapp-vite source compiler provider. Register it in `weapp.compilerPlugins`; the host drives transforms, watch invalidation and WXSS emission.

```ts
import { defineConfig } from 'weapp-vite/config'
import { stylexCompiler } from 'weapp-stylex/weapp-vite'
export default defineConfig({
  weapp: { srcRoot: 'src', compilerPlugins: [stylexCompiler()] },
})
```

This entry handles native JS/TS scripts. Vue SFC preprocessing uses `createStylex`. Compilation and generated filename conflicts surface through host diagnostics.

<a id="api-createStylex"></a>
## createStylex

```ts
createStylex(options: StylexCompilerOptions = {}): StylexIntegration
```

Named export of the weapp-vite entry. Returns two parts sharing one `StylexSession`: raw SFC pre-plugins and a native compiler/output provider. Register **both fields from one call**. Separate calls break their shared metadata/output contract.

```ts
import { defineConfig } from 'weapp-vite/config'
import { createStylex } from 'weapp-stylex/weapp-vite'
const sx = createStylex({ backend: 'auto' })
export default defineConfig({
  plugins: sx.vitePlugins,
  weapp: { srcRoot: 'src', compilerPlugins: [sx.compilerPlugin] },
})
```

The Vite half transforms raw SFC scripts before framework compilation with `sfcOnly: true` and `emitStyles: false`; the native half owns WXSS emission. Raw SFCs stay on Babel even in `auto`, protecting template-only bindings. Use this factory for Wevu/SFC and native H5. H5 uses host page/component CSS metadata; official runtime CSS injection stays disabled.

<a id="api-StylexIntegration"></a>
## StylexIntegration

Public return interface of `createStylex`, exported from `weapp-stylex/weapp-vite` and `@weapp-stylex/weapp-vite`. It retains the exact `vitePlugins` hooks and `compilerPlugin` provider. Exporting an inferred integration from a configuration library emits a reference to this public interface, so consumers do not need to declare the shared compiler directly. The adapter also re-exports the compiler's `PluginHost`, `StyleBundle`, `WebPluginHost` and `WebServer` types so destructuring `vitePlugins` keeps emitted declarations portable.

<a id="api-stylexTaro"></a>
## stylexTaro

```ts
stylexTaro(ctx: IPluginContext, options: StylexCompilerOptions = {}): void
```

Named and default export of `weapp-stylex/taro` or `@weapp-stylex/taro`. Taro supplies required `ctx`; the function registers Vite and Webpack hooks and returns nothing. Configure the plugin path instead of invoking it in application code:

```ts
export default {
  plugins: [[require.resolve('weapp-stylex/taro'), { backend: 'babel' }]],
}
```

Supported TARO_ENV values are weapp, alipay, tt and h5; h5 maps to compiler web. Unknown targets and explicit target conflicts fail. Supports Taro React/Vue 3 on the verified Vite/Webpack 5 hosts. The plugin injects Webpack session state, stable loader identity and cache metadata; no manual loader recipe is required. `StylexWebpackPlugin` is not a public package export.

<a id="api-stylexLoader"></a>
## stylexLoader

```ts
stylexLoader(this: /* Webpack LoaderContext<StylexCompilerOptions> with stylexSession */, code: string): void
```

Named/default export of `weapp-stylex/taro/loader` or `@weapp-stylex/taro/loader`. Webpack supplies the required loader context and source. The Taro plugin must inject `stylexSession`. Return is `void`; asynchronous output, serialized-map decoding and errors go through `this.async()` callback.

```ts
const loaderPath = require.resolve('weapp-stylex/taro/loader')
```

The path is public for plugin/host resolution, not a self-contained manual loader setup. Calling it without its context/session fails. Compiler failures use the callback; dependencies and warnings use Webpack APIs. The context type itself is not exported.

<a id="api-stylexUniApp"></a>
## stylexUniApp

```ts
stylexUniApp(options: StylexCompilerOptions = {}): StylexUniAppPlugins
```

Named/default export of `weapp-stylex/uni-app` or `@weapp-stylex/uni-app`. Returns an array to spread **after `uni()`**. It resolves DCloud’s matching `@vue/compiler-sfc` parser instead of substituting a workspace Vue parser.

With pnpm's isolated installation, consumers can install only the `weapp-stylex` facade. The adapter resolves its runtime forwarding dependencies using physical package identities while preserving DCloud's symlink settings; no extra direct `@weapp-stylex/core` dependency is needed.

```ts
import uniImport from '@dcloudio/vite-plugin-uni'
import { defineConfig } from 'vite'
import { stylexUniApp } from 'weapp-stylex/uni-app'
const uni = (uniImport as unknown as { default?: typeof uniImport }).default ?? uniImport
export default defineConfig({ plugins: [uni(), ...stylexUniApp()] })
```

Supported UNI_PLATFORM values are mp-weixin, mp-alipay, mp-toutiao and h5; h5 maps to compiler web. The config hook rejects unsupported platforms and explicit target conflicts. Missing/mismatched DCloud parser dependencies can fail during factory setup. Vue 2 and uni-app x are outside the stable contract.

<a id="api-StylexUniAppPlugins"></a>
## StylexUniAppPlugins

Public array interface returned by `stylexUniApp`, exported from `weapp-stylex/uni-app` and `@weapp-stylex/uni-app`. It preserves the platform guard, compiler and web plugin hooks, including array spreading and indexing. Configuration libraries can export the inferred return value while keeping generated declarations portable through these public entry points. The adapter also re-exports `PluginHost`, `StyleBundle`, `WebPluginHost` and `WebServer` as types, preserving declaration emission when the returned array is spread into a new exported array.

## Host versions and validation boundary

The framework peers are optional on adapters: install the host used by your application. Their supported ranges are deliberately kept separate.

| Adapter | Declared framework peer | Configured example baseline |
| --- | --- | --- |
| weapp-vite | `weapp-vite >=7.4.0 <8` | weapp-vite/Wevu 7.4.0 with Vite 8.3.4 |
| Taro | `@tarojs/service >=4.3.0 <4.4.0`; `webpack ^5.91.0` | Taro 4.3.0, Vite 4.5.14 / Webpack 5.91.0 |
| uni-app | `@dcloudio/vite-plugin-uni 3.0.0-alpha-5030120260930001` | Matching vue3 channel, Vue 3.4.21 / Vite 5.2.8 |

Published libraries retain Node `^22.22.1 || >=24.11.0`; the private workspace and docs use `^22.23.4 || ^24.22.1 || >=26.12.1`. CI targets 22.23.4 and 24.22.1, with separate isolated consumers on the library minimums 22.22.1 and 24.11.0. Avoid global overrides that unify incompatible host Vite/Vue/Babel versions. Shared StyleX compilation remains on Babel 7. Static builds, headless interaction and real WeChat IDE evidence are distinct checks; consult [examples](/examples/) for acceptance records and the [dependency record](https://github.com/weapp-stylex/weapp-stylex/blob/main/docs/dependency-upgrade-2026-10-13.md) for this upgrade's verification status.

<a id="api-uniStylexTarget"></a>
## taroStylexTarget and uniStylexTarget

`taroStylexTarget(platform: string | undefined)` maps `weapp`, `alipay`, `tt` and `h5` to the shared `StylexTarget`; `h5` maps to `web`. `uniStylexTarget(platform: string | undefined)` accepts `mp-weixin`, `mp-alipay`, `mp-toutiao` and `h5`. Unknown or missing platforms throw. These helpers are for host integration authors; applications do not need to call them.
