## 样式没有生效

确认适配器已经注册，定义模块进入宿主构建模块图，产物包含生成的 `stylex.wxss` import。默认导入为 `weapp-stylex`、`weapp-stylex/core`、`@weapp-stylex/core` 和 `@stylexjs/stylex`；显式设置 `importSources` 会替换这些默认值。

Wevu SFC 应注册同一个 `createStylex()` 工厂的两个字段，不要使用两个独立 session。Page data 绑定 `attrs()` 的结果，不是 `create()` 的映射对象。

具体症状、诊断步骤、修复和验收请按[问题排查](/zh/troubleshooting/)执行。

## Runtime 有默认导出吗？

`weapp-stylex` 和 `weapp-stylex/core` 通过 `export *` 转导出官方具名 API 与类型。使用 `import * as stylex from 'weapp-stylex'` 或具名导入，根/core runtime 没有默认导出。用户编写的样式模块仍可默认导出编译后的映射。构建适配器使用各自的[子路径导出](/zh/aggregate-package/)。

## 动态值或主题不生效

同时绑定 class 与 style。token 定义命名为 `tokens.stylex.ts`，样式/主题直接导入它。隔离组件根节点绑定主题 class。确认所选微信基础库支持产物使用的 CSS 自定义属性。

## stylex.wxss 文件名冲突

`stylex.wxss` 由插件管理。重命名手写文件，保留常规 WXSS 入口，插件会自动注入 import。不要取消冲突检查或将生成 CSS 复制到每个页面。

## 为什么 16 仍是 16px？

这是官方 StyleX 的单位语义。微信响应式单位请写 `'16rpx'`。StyleX 产物在框架尺寸转换之后输出，不会二次转换。

## 工具链版本不匹配

StyleX 编译器保留 Babel 7，不要把 weapp-vite 的 Babel 8 要求全局套用。Taro 使用 Vite 4、uni-app 使用 Vite 5、当前 weapp-vite 使用 Vite 8，应按 workspace 隔离。

## 当前支持范围

已支持：微信主包、页面、组件和普通分包；原生、Wevu、Taro React/Vue 3 与 uni-app Vue 3。

尚未形成稳定契约：独立分包、其他小程序平台、Vue 2、uni-app x、自定义 WXML `sx` 属性和 stateful HMR。WXML 不能直接调用 StyleX 函数，编译器也不会从模板反推 TS 模块。

沿用官方 StyleX API 语义，不代表所有浏览器选择器、媒体特性和 CSS 属性都受 WXSS 支持。编译能力、输出语法与所选微信基础库中的行为需要分别检查。主题和动态值依赖 CSS 自定义属性。[Runtime 参考](/zh/api/runtime/)与[实践教程](/zh/recipes/)说明平台绑定契约。

[2026-10-09 IDE 记录](https://github.com/weapp-stylex/weapp-stylex/blob/main/docs/ide-validation-2026-10-09.md)保留七种产物分别验收的结果，完整 suite 仍待验收。它是有日期的记录，不是当前全部通过或最低基础库版本承诺。[示例页](/zh/examples/)提供可复现验收命令。

提交 [GitHub issue](https://github.com/weapp-stylex/weapp-stylex/issues)时请附框架版本、配置、最小共享模块和相关 WXSS 产物。

## 为什么 auto 仍使用 Babel？

`auto` 只加速已验证的写法。主题 API、跨文件 token、自定义 Babel 配置、不支持的 runtime 子路径、未验证的编译期表达式及原始 SFC 脚本保留 Babel。SWC 0.19.0 可能删除仅在模板中使用的绑定，因此适配器保护这些脚本。每种回退原因在 session 内只提示一次。

原生依赖缺失时，启用可选依赖重新安装并重启构建。Babel 可以继续使用；项目完全处于支持范围时才使用强制 `swc`。未知错误不会被回退隐藏。可复现测量和完整构建收益的边界见[性能说明](/zh/performance/)。
