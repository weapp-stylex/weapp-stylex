## 平台与自动推断

现有原生、Wevu、Taro React/Vue 3 和 uni-app Vue 3 适配器均支持微信、支付宝、抖音与 H5。平台从活动宿主推断，通常不需要设置 `target`。可选 `target` 使用 compiler 的统一名称 `weapp | alipay | tt | web`；与宿主不一致时构建报错。直接创建 compiler session 时默认 `weapp`。

| 目标 | weapp-vite CLI | Taro CLI | uni-app CLI | 模板 / 样式 |
| --- | --- | --- | --- | --- |
| 微信 | `-p weapp` | `--type weapp` | `-p mp-weixin` | `.wxml` / `.wxss` |
| 支付宝 | `-p alipay` | `--type alipay` | `-p mp-alipay` | `.axml` / `.acss` |
| 抖音 | `-p tt` | `--type tt` | `-p mp-toutiao` | `.ttml` / `.ttss` |
| H5 | `-p web` | `--type h5` | `-p h5` | 浏览器 CSS |

原生与 Wevu 的跨端配置统一使用 `createStylex()`，同时注册返回的 `vitePlugins` 与 `compilerPlugin`；H5 在项目根目录提供引用 `/@weapp-vite/web/entry` 的 `index.html`。`stylexCompiler()` 保留原生小程序的兼容入口。各小程序平台使用自己的项目配置，不复制微信配置到其他目标。

小程序默认变量选择器为 `page`；H5 保留 `:root`，weapp-vite 页面 Shadow DOM 使用 `:host` 默认值，组件继承页面主题。Taro/uni-app H5 生产构建生成带 hash 的独立 CSS 并引用到 HTML；weapp-vite 将 CSS 放入页面/组件的 Web metadata。开发服务会更新样式，允许完整刷新。原子规则仍全局聚合排序，官方 runtime CSS injection 保持关闭。

数值和 `px` 保持 StyleX 原义；H5 静态 `rpx` 遵循宿主转换策略，动态值使用浏览器标准单位。不将 H5 编译或浏览器验证视为支付宝/抖音 IDE 或真机已验收。

## 包入口

| 包 | 用途 |
| --- | --- |
| `weapp-stylex` | 聚合 runtime、类型和各框架适配器子路径 |
| `@weapp-stylex/core` | 官方 runtime API 与类型 |
| `@weapp-stylex/compiler` | 共享构建核心，ESM/CJS |
| `@weapp-stylex/weapp-vite` | 原生与 Wevu 适配器 |
| `@weapp-stylex/taro` | Taro 插件，ESM/CJS 与 loader 导出 |
| `@weapp-stylex/uni-app` | DCloud Vue 3 适配器 |

推荐使用[聚合包](/zh/aggregate-package/)，最新发布版本以 [npm](https://www.npmjs.com/package/weapp-stylex) 为准。

## Runtime

`weapp-stylex`、`weapp-stylex/core` 和 `@weapp-stylex/core` 转导出 `@stylexjs/stylex` 的官方具名 runtime API 与类型。根/core runtime 没有默认导出，使用 namespace 或具名导入；根入口不会加载构建适配器。默认也识别直接导入 `@stylexjs/stylex`。

```ts
import * as stylex from 'weapp-stylex'
// 或 import { create, attrs, props } from 'weapp-stylex'
```

完整导出见 [runtime 参考](/zh/api/runtime/)，样式契约见[类型参考](/zh/api/types/)。原生/Vue 使用 `attrs()` 的 class/style 字符串，Taro React 在 `View` 展开 `props()`。

## 工具链版本矩阵

以下是仓库示例版本，不代表同一主版本内的每个发布都已验证。适配器 peer 声明约束安装，真实运行验收有独立的[日期记录](/zh/examples/)。

| 宿主 | 示例基线 | Builder |
| --- | --- | --- |
| 原生微信 | weapp-vite 7.4.0 | Vite 8.3.4 |
| Wevu | wevu 7.4.0 + weapp-vite 7.4.0 | Vite 8.3.4 |
| Taro React | Taro 4.3.0 + React 18.3.1 | Vite 4.5.14 或 Webpack 5.91.0 |
| Taro Vue 3 | Taro 4.3.0 + Vue 3.5.43 | Vite 4.5.14 或 Webpack 5.91.0 |
| uni-app Vue 3 | DCloud `3.0.0-alpha-5030120260930001` + Vue 3.4.21 | Vite 5.2.8 |

weapp-vite 适配器声明 `>=7.4.0 <8`；Taro 适配器声明 `@tarojs/service >=4.3.0 <4.4.0` 和 `webpack ^5.91.0`；uni-app 适配器固定为上面的 DCloud 插件通道。Optional peer 表示不会自动安装未使用的宿主，不表示可以省略所选宿主。

官方 StyleX runtime/plugin 为 0.19.1。共享编译器使用 Babel 7，weapp-vite 保留自身 Babel 8。不兼容的 Vite/Vue/Babel 分组分开管理，不要用全局 override 统一。DCloud runtime/plugin 包需匹配同一通道及其 SFC parser。

## 通用选项

```ts
interface StylexCompilerOptions {
  target?: 'weapp' | 'alipay' | 'tt' | 'web'
  backend?: 'babel' | 'auto' | 'swc'
  importSources?: readonly string[]
  babel?: Partial<Options> // @stylexjs/babel-plugin Options
}
```

`importSources` 会**替换**默认列表 `['weapp-stylex', 'weapp-stylex/core', '@weapp-stylex/core', '@stylexjs/stylex']`，增加来源时请保留默认项。`babel` 传给官方 StyleX 插件，并不是通用 Babel pipeline 配置。

```ts
const stylex = createStylex({
  importSources: ['weapp-stylex', 'weapp-stylex/core', '@weapp-stylex/core', '@stylexjs/stylex', 'my-stylex-facade'],
})
```

平台固定使用 `classNamePrefix: 'sx'`、`debug: false`、`dev: false`、`test: false`、`runtimeInjection: false` 和 `styleResolution: 'application-order'`。规则聚合固定 `legacyDisableLayers: true` 与 `useLayers: false`。不要覆盖 custom module resolution，它负责将跨模块主题连接到宿主 resolver。

## 构建核心 API

适配器作者可以使用 `StylexSession`、`createVitePlugins`、`WxssEmitter`、`processRules` 与 `sourceId`。应用项目优先使用框架适配器。宿主和输出契约参见[架构指南](/zh/architecture/)与[源码](https://github.com/weapp-stylex/weapp-stylex/tree/main/packages/compiler/src)。

[编译器参考](/zh/api/compiler/)介绍公开类、宿主类型与生命周期归属；[共享模块教程](/zh/recipes/shared-modules/)展示无需直接管理 session 的应用写法。

## 编译后端

默认 `backend: 'babel'` 使用官方 Babel 7，同时启用 AST 复用与 session 缓存。`backend: 'auto'` 为已验证的写法选择 SWC，每个 session 对同一种回退原因只提示一次。`backend: 'swc'` 强制使用 SWC，不支持或不可用时明确报错。

```ts
stylexCompiler({ backend: 'auto' })
createStylex({ backend: 'auto' }) // Wevu：注册工厂的两个字段
stylexUniApp({ backend: 'auto' })
// Taro 配置：
const plugins = [[require.resolve('weapp-stylex/taro'), { backend: 'auto' }]]
```

SWC 覆盖静态样式、简单的局部动态样式、条件合并、常规 shorthand/null、keyframes 与 firstThatWorks。主题和常量、编译期导入、SWC 不接受的 runtime 子路径、非空 `babel` 配置及未验证的表达式求值继续使用 Babel。原始 Vue SFC 脚本也保留 Babel：SWC 0.19.0 会删除只在模板中使用的绑定；独立 TS/JS 样式文件仍可加速。原始导入和主题身份算法保持一致。

`@stylexswc/rs-compiler@0.19.0` 是按需加载的可选原生依赖，不需要安装 Rust。省略可选依赖时 Babel 仍可使用；`auto` 提示并使用 Babel，`swc` 给出重装建议。默认 Babel 与 runtime 入口不会加载原生模块。语法错误、解析失败及未知编译错误会正常报告。

宿主作者可提供 `TransformHost.diagnostic(diagnostic)`，接收包含文件、可确定位置和修复建议的结构化诊断。Vite、weapp-vite 与 Webpack 适配器通过原生诊断接口展示；SFC 位置指向 `.vue` 原文件。参见[性能与边界](/zh/performance/)。

构建失败时，先按[问题排查](/zh/troubleshooting/)定位原因，再调整后端或依赖约束。[迁移教程](/zh/recipes/migration/)介绍先建立基线的接入流程。
