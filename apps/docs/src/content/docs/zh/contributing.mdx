## Workspace 工作流

私有仓库与文档站使用 repoctl `6.0.1`、pnpm `12.11.2` 与 Node.js `^22.23.4 || ^24.22.1 || >=26.12.1`，CI 使用 Node 22.23.4 和 24.22.1。发布库继续保持 `^22.22.1 || >=24.11.0`，独立 ESM/CJS 消费者在 Node 22.22.1、24.11.0 上检查。Git hooks 改由 Lefthook 管理，通过 repoctl 升级同步 `lefthook.yml`，不要恢复旧 Husky 或 lint-staged 文件。通过 `corepack pnpm exec repo new <name> --template <key>` 创建包，保持适配器精简，共享编译行为放在 `@weapp-stylex/compiler`。

六个发布库统一使用 tsdown `0.23.1`：core 与 weapp-vite 保留 ESM-only，其余四包保留 ESM/CJS，所有代码入口均提供声明文件。TypeScript 保持 `6.0.3`：TypeScript 7 移除了根入口的旧 Compiler API，repoctl、Astro check 与 TypeScript ESLint 也尚不支持该主版本。共享 StyleX 编译器保留 Babel 7，各框架工具链单独解析。升级决策和验证状态见 [2026-10-13 依赖记录](https://github.com/weapp-stylex/weapp-stylex/blob/main/docs/dependency-upgrade-2026-10-13.md)。

编译器改动提交前执行完整[验证流程](/zh/examples/)。可发布包的变更使用 `corepack pnpm change`，文档改动不会发布 npm 包。

受管 `release.yml` 还提供 nightly：每天 UTC 19:17（北京时间 03:17）从 `main` 发布六包到 npm `snapshot-nightly`，也支持手动触发。使用 `pnpm add weapp-stylex@snapshot-nightly` 安装。快照通过 npm OIDC 发布，不消费发布意图、不推进 `latest`。提交可复现问题时，使用工作流产物报告中的精确快照版本。

## 文档源码

[stylex.weapp.dev](https://stylex.weapp.dev/) 起始于 repoctl Nimbus 模板，使用 Nimbus `0.18.0` 和 Astro `7.3.8`，布局与组件由项目维护。内容位于 `apps/docs/src/content/docs/`：英文使用根相对路径，中文放在 `zh/` 下的对应文件；教程与 API 参考使用各自子目录。

```sh
corepack pnpm --filter docs dev
corepack pnpm --filter docs lint
corepack pnpm --filter docs typecheck
corepack pnpm --filter docs build
corepack pnpm --filter docs check:site
corepack pnpm exec node scripts/test-docs-browser.mjs
corepack pnpm --filter docs test
corepack pnpm --filter docs preview
```

生产构建生成 Pagefind 搜索。`scripts/test-docs-browser.mjs` 在独立文档工作流中 headless 检查双语搜索、快捷键与焦点、代码复制、主题持久化、语言切换、移动导航和无 JavaScript 内容，并关闭自己创建的浏览器与服务。开发服务器不提供完整搜索索引。

发布新页面前补齐两个语言版本，保持代码行为与公开链接一致。注册传达信息的 MDX 组件时，同时提供 Markdown 文本转换；除了视觉页面，还需检查自定义 tabs/steps 在 Markdown 导出中的内容。[实践教程](/zh/recipes/)应展示真实框架绑定，[API 参考](/zh/api/)应与包导出及源码类型一致。

验收记录保留日期。[2026-10-09 运行记录](https://github.com/weapp-stylex/weapp-stylex/blob/main/docs/ide-validation-2026-10-09.md)区分各产物分别通过与完整 suite 仍待验收，后续文档编辑不能将历史结果改写成没有证据的当前验收成功。

## 工具读取入口

每页提供 `/index.md` 和 `/index.mdx`。`/llms.txt` 列出文档，`/zh/llms.txt` 列出中文页面，`/llms-full.txt` 包含完整公开文本。它们与网站使用同一内容源生成。

## 部署

repoctl 将文档站登记为 `stylex`。`main` 更新部署到[preview.stylex.weapp.dev](https://preview.stylex.weapp.dev/)，完整稳定 npm 发布记录触发[stylex.weapp.dev](https://stylex.weapp.dev/)更新。Cloudflare Workers Static Assets 通过独立 Worker 和自定义域名托管静态 `dist/`。canonical、语言 alternate、sitemap 和 Markdown/AI 地址统一使用所选渠道的 origin。预览站显示未发布提示并禁用搜索引擎索引，保留 Pagefind 站内搜索。

在仓库根目录验证两个构建渠道，不上传产物：

```sh
corepack pnpm docs:build
REPO_DOCS_CHANNEL=preview REPO_DOCS_URL=https://preview.stylex.weapp.dev corepack pnpm docs:build
```

根构建先准备公开包声明，再执行文档检查及 headless 浏览器交互。部署由受管 `repoctl-docs.yml` 与 `repoctl-docs-deploy.yml` 完成；`Documentation checks` 保留项目专用验证。内部 `docs:deploy:preview` / `docs:deploy:stable` 适配脚本要求受管上下文，不能作为手动生产部署捷径。

GitHub environments `docs-stylex-preview` 和 `docs-stylex-stable` 需要 `CLOUDFLARE_API_TOKEN` 与 `CLOUDFLARE_ACCOUNT_ID`，不要提交凭据。首次受管正式基线等待合格的完整稳定发布，在此之前保留当前线上版本。部署失败使用同一发布记录重试，不重新发布 npm 包。接入和恢复参见[部署手册](https://github.com/weapp-stylex/weapp-stylex/blob/main/docs/site-deployment.md)。
