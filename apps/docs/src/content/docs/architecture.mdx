## Pipeline

Source modules → official StyleX Babel 7 / optional SWC backend → module metadata → rule aggregation → WXSS output planning → host asset emission.

`@weapp-stylex/compiler` owns transforms, resolver identity, SFC maps, metadata and WXSS planning. Framework adapters handle host hooks, lifecycle and emission. The runtime facade stays a thin official re-export.

The runtime root/core uses named re-exports and has no default export. Its JavaScript composes compiled mappings into attributes/props; build tools stay on explicit subpaths. See [public entry points](/aggregate-package/) and the [build-core reference](/api/compiler/).

## Metadata and graph lifetime

Each normalized module ID owns rules and dependencies. A transform replaces that module's metadata. Watch rebuilds retain unchanged cached modules, invalidate dependents on change, and prune modules that are no longer reachable. Token dependencies remain tracked even when their runtime imports disappear.

`closeBundle` does not clear an active watcher. Final watcher shutdown releases session state. Stateful HMR patches are not part of the current contract; output consistency takes priority.

## Vue and Webpack

SFC preprocessing changes script contents only and composes sourcemaps. Template compilation and framework macros stay with the host. Vite virtual script requests are skipped. uni-app uses its own compatible parser.

Taro's Webpack pre-loader runs before Babel/Vue processing and records metadata in module `buildInfo`. `processAssets` collects cached rules and injects WXSS after the host finishes its own styles.

Vue-loader rereads the raw SFC for inline script, template and style requests. The Webpack pre-loader transforms that document before Vue-loader selects the block, reusing session caches. A stable loader identity prevents duplicate processing from cloned Vue-loader rules. External scripts follow the ordinary script path; unknown custom blocks keep the host's default behavior.

## Output planning

When StyleX rules exist, the emitter writes the aggregated stylesheet as `stylex.wxss` beside each required WXSS directory. Sibling styles import it using `@import "./stylex.wxss";`. This can repeat the stylesheet across directories; it is not a separate stylesheet for each source module.

An emitted WXML entry with matching JavaScript and no authored WXSS receives a same-name companion. `app.wxss` is also created when needed. Companions load generated styles without changing the host's page/component registration. See [components and ordinary subpackages](/recipes/components-subpackages/).

Rules are aggregated and deduplicated. CSS layers, browser specificity polyfills and runtime stylesheet injection are disabled. Default variable `:root` selectors map to `page`.

This is a compile/output boundary. It does not polyfill browser selectors, DOM behavior or unsupported WXSS properties; target base-library behavior requires runtime validation. [Tokens and themes](/recipes/tokens-themes/) show the explicit root binding.

Output is idempotent. User-owned filename collisions fail with an explicit error. Watch rebuilds remove only plugin-owned stale files/imports. An initial build without StyleX does not change assets.

New assets use host emission APIs where available. weapp-vite `7.4` exposes a read-only bundle for new keys, so its adapter uses the documented file-output compatibility path.

## Backend and cache boundary

A shared backend interface returns code, sourcemaps and official-format rules. Babel reuses the analysis AST; the AST belongs to a single transform and is never stored in a mutable cache. SWC is loaded only after conservative AST capability checks. Raw SFC scripts retain Babel so template-only bindings and imports survive.

Only imports used in StyleX compile-time evaluation are pre-resolved. Ordinary component imports and runtime styles remain in the host graph. Sessions coalesce concurrent source/token work, reuse filesystem and resolver facts within a build, and cache transforms by physical ID, source hash, compiler/options fingerprint, actual backend and dependency signatures. Non-empty custom Babel options disable transform caching because callbacks may read external state.

Changes invalidate dependent results; configuration/manifest changes revalidate identities and caches. Generation and per-module request checks stop stale asynchronous jobs from restoring removed metadata. Cached modules survive watch output hooks, unreachable modules are pruned, and final watcher shutdown releases caches. Webpack adds the fingerprint to the host cache version and appends compiler build dependencies, retaining host cache settings and rules in buildInfo.
