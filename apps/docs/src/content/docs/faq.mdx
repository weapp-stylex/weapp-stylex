## No styles appear

Confirm the adapter is registered, the definition module enters the host build graph, and the output contains generated `stylex.wxss` imports. Default imports are `weapp-stylex`, `weapp-stylex/core`, `@weapp-stylex/core` and `@stylexjs/stylex`; an explicit `importSources` list replaces them.

For Wevu SFCs, register both fields of the same `createStylex()` factory. Do not use two separate sessions. Bind the result of `attrs()`, not the `create()` mapping, into Page data.

Follow [troubleshooting](/troubleshooting/) for symptoms, diagnostic steps, repairs and acceptance checks.

## Does the runtime have a default export?

`weapp-stylex` and `weapp-stylex/core` forward official named APIs and types with `export *`. Use `import * as stylex from 'weapp-stylex'` or named imports; the root/core runtime has no default export. A user-authored style module may still default-export its compiled mapping. Build adapters have their own [subpath exports](/aggregate-package/).

## Dynamic values or themes fail

Bind both class and style. Name token definitions `tokens.stylex.ts` and import them directly from styles/themes. Apply theme classes on isolated component roots. Confirm the chosen WeChat base library supports the CSS custom properties used in your output.

## stylex.wxss filename conflict

`stylex.wxss` is plugin-owned. Rename your authored file and keep your regular WXSS entry; the plugin injects imports automatically. Do not remove collision checks or copy generated CSS into every page.

## Why did 16 stay 16px?

This preserves official StyleX semantics. For WeChat responsive units, write `'16rpx'`. StyleX output runs after the framework's dimension conversion, so it is not transformed a second time.

## Toolchain mismatch

Keep Babel 7 for the StyleX compiler. weapp-vite's Babel 8 requirements must not replace it globally. Taro uses Vite 4, uni-app uses Vite 5, while current weapp-vite uses Vite 8; resolve them per workspace.

## Current support

Supported: WeChat main package, pages, components, ordinary subpackages; native, Wevu, Taro React/Vue 3 and uni-app Vue 3.

Not yet a stable contract: independent subpackages, other mini-program platforms, Vue 2, uni-app x, custom WXML `sx` attributes and stateful HMR. WXML cannot call StyleX functions directly, and the compiler does not infer TS modules from templates.

Official StyleX API semantics do not establish that every browser selector, media feature or CSS property is supported by WXSS. Compile-time support, emitted syntax and behavior on a selected WeChat base library are separate checks. Themes and dynamic values depend on CSS custom properties. See the [runtime reference](/api/runtime/) and [practical recipes](/recipes/) for the platform-specific binding contract.

The [2026-10-09 IDE record](https://github.com/weapp-stylex/weapp-stylex/blob/main/docs/ide-validation-2026-10-09.md) records individual acceptance for seven artifacts and a still-pending complete suite. Treat that as a dated result, not a current blanket pass or minimum-base-library guarantee. [Examples](/examples/) provide the reproducible validation commands.

Report issues with framework versions, config, a minimal shared module and the affected WXSS artifact in [GitHub issues](https://github.com/weapp-stylex/weapp-stylex/issues).

## Why does auto use Babel?

`auto` promises compatibility with a verified subset, not acceleration of every module. Theme APIs, cross-file token imports, custom Babel options, unsupported runtime subpaths, unverified compile-time expressions and raw SFC scripts retain Babel. SWC 0.19.0 can delete template-only SFC bindings, so the adapter protects them. Each fallback reason is reported once during a session.

If the native dependency is absent, install with optional dependencies and restart the build. Babel remains usable without it. Use `swc` only for a project within the documented subset; unknown errors are not hidden by fallback. See [performance](/performance/) for reproducible measurements and full-build limits.
