## Runtime

`weapp-stylex`, `weapp-stylex/core` and `@weapp-stylex/core` re-export official named runtime APIs and types from `@stylexjs/stylex`. The root/core runtime has no default export. Use a namespace or named import; the package root never loads build adapters. Direct `@stylexjs/stylex` imports are recognized by default too.

```ts
import * as stylex from 'weapp-stylex'
// Or import { create, attrs, props } from 'weapp-stylex'
```

See the [runtime reference](/api/runtime/) for exports and the [type reference](/api/types/) for style contracts. Native/Vue uses `attrs()` class/style strings; Taro React spreads `props()` on `View`.

## Toolchain matrix

These are the repository's example versions, not a promise that every release in the same major is verified. Adapter peer declarations define installation constraints; real runtime acceptance has its own [dated records](/examples/).

| Host | Example baseline | Builder |
| --- | --- | --- |
| Native WeChat | weapp-vite 7.4.0 | Vite 8.3.4 |
| Wevu | wevu 7.4.0 + weapp-vite 7.4.0 | Vite 8.3.4 |
| Taro React | Taro 4.3.0 + React 18.3.1 | Vite 4.5.14 or Webpack 5.91.0 |
| Taro Vue 3 | Taro 4.3.0 + Vue 3.5.43 | Vite 4.5.14 or Webpack 5.91.0 |
| uni-app Vue 3 | DCloud `3.0.0-alpha-5030120260930001` + Vue 3.4.21 | Vite 5.2.8 |

The weapp-vite adapter declares `>=7.4.0 <8`; the Taro adapter declares `@tarojs/service >=4.3.0 <4.4.0` and `webpack ^5.91.0`; the uni-app adapter pins the DCloud plugin channel above. Optional peers mean unused hosts are not installed automatically, not that a selected host can be omitted.

Official StyleX runtime/plugin is 0.19.1. The shared compiler uses Babel 7; weapp-vite keeps its own Babel 8. Keep the incompatible Vite/Vue/Babel groups separate instead of unifying them with global overrides. DCloud runtime/plugin packages must use the matching channel and its SFC parser.

## Common options

```ts
interface StylexCompilerOptions {
  backend?: 'babel' | 'auto' | 'swc'
  importSources?: readonly string[]
  babel?: Partial<Options> // @stylexjs/babel-plugin Options
}
```

`importSources` **replaces** the default list `['weapp-stylex', 'weapp-stylex/core', '@weapp-stylex/core', '@stylexjs/stylex']`. Include the defaults when adding another source. Babel options are passed to the official StyleX plugin, not to a general-purpose Babel pipeline.

```ts
const stylex = createStylex({
  importSources: ['weapp-stylex', 'weapp-stylex/core', '@weapp-stylex/core', '@stylexjs/stylex', 'my-stylex-facade'],
})
```

Platform settings are enforced: `classNamePrefix: 'sx'`, `debug: false`, `dev: false`, `test: false`, `runtimeInjection: false`, and `styleResolution: 'application-order'`. Rule aggregation fixes `legacyDisableLayers: true` and `useLayers: false`. Do not override custom module resolution; it connects cross-module themes to the host resolver.

## Build-core API

Adapter authors can use `StylexSession`, `createVitePlugins`, `WxssEmitter`, `processRules` and `sourceId`. Applications should use the framework adapter. See the [architecture guide](/architecture/) and the [source](https://github.com/weapp-stylex/weapp-stylex/tree/main/packages/compiler/src) for host and output contracts.

The [compiler reference](/api/compiler/) documents public classes, host types and lifecycle ownership; [shared-module recipes](/recipes/shared-modules/) show application-level usage without direct session management.

## Backend selection

The default `backend: 'babel'` uses official Babel 7 with AST reuse and session caching. `backend: 'auto'` selects SWC for the verified subset and reports compatibility fallbacks once per reason per session. `backend: 'swc'` requires SWC and fails explicitly when unsupported or unavailable.

```ts
stylexCompiler({ backend: 'auto' })
createStylex({ backend: 'auto' }) // Wevu: register both fields
stylexUniApp({ backend: 'auto' })
// Taro config:
const plugins = [[require.resolve('weapp-stylex/taro'), { backend: 'auto' }]]
```

SWC supports static styles, simple local dynamic styles, conditional merges, common shorthands/null, keyframes and firstThatWorks. Themes/constants, compile-time imports, runtime import subpaths rejected by SWC, non-empty `babel` options and unverified expression folding use Babel. Raw Vue SFC scripts also use Babel: SWC 0.19.0 removes bindings used only by templates. Shared TS/JS style files can still accelerate. Original imports and theme identities are preserved.

`@stylexswc/rs-compiler@0.19.0` is an optional, lazy native dependency. Rust is unnecessary. Omitting optional dependencies keeps Babel usable; `auto` warns and uses Babel, while `swc` explains how to reinstall. Default Babel and the runtime entry never load the addon. Syntax, resolver and unknown compiler errors are reported rather than silently retried.

Host authors may provide `TransformHost.diagnostic(diagnostic)` to receive structured warnings/errors with source location and repair hints. Vite, weapp-vite and Webpack adapters forward them through native diagnostics; SFC positions refer to the `.vue` file. See [performance and scope](/performance/).

If a build fails, follow [troubleshooting](/troubleshooting/) before changing backend or dependency constraints. [Migration](/recipes/migration/) explains a baseline-first rollout.
