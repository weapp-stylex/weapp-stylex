## Register both integration fields

```sh
pnpm add weapp-stylex
```

```ts
import { createStylex } from 'weapp-stylex/weapp-vite'
import { defineConfig } from 'weapp-vite/config'

const stylex = createStylex()
export default defineConfig({
  plugins: stylex.vitePlugins,
  weapp: { srcRoot: 'src', compilerPlugins: [stylex.compilerPlugin] },
})
```

Both fields share one session. Do not register an additional `stylexCompiler()` instance. The Vite side processes raw SFC scripts; the compiler side writes native WXSS.

## Reactive bindings

Import `computed` and `ref` from **wevu**. Define styles in an ordinary module, then compose them in the consumer:

```vue
<script setup lang="ts">
import * as stylex from 'weapp-stylex'
import { computed, ref } from 'wevu'
import { styles } from './styles'

const active = ref(false)
const width = ref(80)
const attrs = computed(() =>
  stylex.attrs(styles.root, active.value && styles.active),
)
const meter = computed(() => stylex.attrs(styles.meter(width.value)))
</script>

<template>
  <view :class="attrs.class" :style="attrs.style" @tap="active = !active">
    <text>Shared StyleX</text>
    <view :class="meter.class" :style="meter.style" />
  </view>
</template>
```

Bind both `.class` and `.style`: dynamic values can produce inline CSS custom properties. Templates, macros, lifecycle hooks and `<style>` remain Wevu's responsibility.

## JSX and external modules

JSX/TSX consumers can use the official runtime too. Raw `<script>` and `<script setup>` are transformed before SFC compilation, sourcemaps are composed, and virtual script requests are skipped to avoid double transformation. Shared external TS styles are processed as modules.

Explore [wechat-wevu](https://github.com/weapp-stylex/weapp-stylex/tree/main/examples/wechat-wevu), including Vue SFC, a JSX component, themes and a subpackage.

## Other platforms and H5

The WeChat examples above also accept Alipay, Douyin and H5 through the host. See [platform configuration](/configuration/#platforms-and-host-inference) for commands and mappings. Adapters infer the target; an optional `target` must match it. Mini-programs receive `stylex.wxss`, `stylex.acss` or `stylex.ttss`. H5 uses browser CSS; native/Wevu registers both `createStylex()` fields and supplies the Web `index.html`. H5 preserves `:root`; weapp-vite page Shadow DOM receives defaults while components inherit themes. Static rpx follows host policy, numeric/px values remain unchanged, and dynamic values use browser-standard units. Development updates may reload the page. `test:h5` validates production and development browser interactions.

The weapp-vite 7.4 Web runtime is experimental and does not compile Wevu JSX render functions. The example selects an equivalent SFC through the host component resolver for H5 while mini-programs retain the TSX fixture. Shared StyleX modules, themes and dynamic values use the same contract.
