## Configure weapp-vite

```sh
pnpm add weapp-stylex
```

```ts
// vite.config.ts
import { stylexCompiler } from 'weapp-stylex/weapp-vite'
import { defineConfig } from 'weapp-vite/config'

export default defineConfig({
  weapp: { srcRoot: 'src', compilerPlugins: [stylexCompiler()] },
})
```

`stylexCompiler()` supports native JS, TS, JSX and TSX source modules. Use `createStylex()` when your project also contains Vue SFCs.

## Bind class and style explicitly

Import shared declarations from `src/styles.ts` using the [shared module pattern](/styles/).

```ts
// pages/index/index.ts
import * as stylex from 'weapp-stylex'
import { styles } from '../../styles'

Page({
  data: {
    active: false,
    sx: stylex.attrs(styles.root),
    meter: stylex.attrs(styles.meter(80)),
  },
  toggle() {
    const active = !this.data.active
    this.setData({
      active,
      sx: stylex.attrs(styles.root, active && styles.active),
    })
  },
})
```

```xml
<!-- pages/index/index.wxml -->
<view class="{{sx.class}}" style="{{sx.style}}" bindtap="toggle">
  <text>StyleX in WeChat</text>
  <view class="{{meter.class}}" style="{{meter.style}}" />
</view>
```

The same pattern works in a `Component`: store the initial `attrs()` result in `data`, then use `this.setData()` in component methods or observers when props change. Apply the theme class to an isolated component's own root.

## Pages and components without local WXSS

The compiler adds a same-name WXSS companion for pages and isolated components that have no local stylesheet. Each style output directory gets `stylex.wxss`; its siblings import it via `./stylex.wxss`. A build with no StyleX leaves output unchanged.

## Ordinary subpackages

Keep your existing `app.json` subpackage declarations. Shared modules can be used by the main package and ordinary subpackages. Independent subpackages are outside the stable support contract.

See the runnable [wechat-native example](https://github.com/weapp-stylex/weapp-stylex/tree/main/examples/wechat-native), including shared styles, themes, components and a subpackage route.

## Other platforms and H5

The WeChat examples above also accept Alipay, Douyin and H5 through the host. See [platform configuration](/configuration/#platforms-and-host-inference) for commands and mappings. Adapters infer the target; an optional `target` must match it. Mini-programs receive `stylex.wxss`, `stylex.acss` or `stylex.ttss`. H5 uses browser CSS; native/Wevu registers both `createStylex()` fields and supplies the Web `index.html`. H5 preserves `:root`; weapp-vite page Shadow DOM receives defaults while components inherit themes. Static rpx follows host policy, numeric/px values remain unchanged, and dynamic values use browser-standard units. Development updates may reload the page. `test:h5` validates production and development browser interactions.

Native component lifecycles follow the selected platform. The Alipay example enables Component2 and declares `props`, then computes `attrs()` from `nextProps` in `deriveDataFromProps(nextProps)` on creation and before property updates. Keep initial styles in `data`; `this.props` can still contain the previous values in this hook. WeChat and Douyin continue to use `properties` observers.
