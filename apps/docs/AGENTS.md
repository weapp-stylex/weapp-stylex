# Documentation workspace

This is a static Nimbus + Astro documentation site. Run commands in this workspace; install dependencies from the monorepo root after `corepack enable`.

- Content lives in `src/content/docs/`; existing English guides keep their root-level routes, new references/recipes use `api/` and `recipes/`, and Chinese uses `zh/` with matching relative filenames. The English homepage uses `slug: en` at `/en/`; `/` is the client language selector. Keep unconditional root redirects out of Astro and `_redirects`. Selection order is saved manual choice, device time zone (China zones → zh; other valid zones → en), then first browser language when time zone is unavailable. Time zone is an approximation based on device settings. Keep deployment purely static: do not add a Worker or IP lookup for language detection. Direct document routes stay explicit. Point English home links and language alternates to `/en/`. Keep both translations and links in sync.
- The directory tree supplies routes; `src/lib/navigation.ts` owns the shared bilingual navigation groups, order, breadcrumbs and previous/next links. Add new published pages to both language trees and this module. Desktop/mobile navigation must use the same definition, include every published page once and mark the current route. Edit links must use the actual source file path, including nested `index.mdx`, rather than assuming Nimbus entry IDs are filenames.
- Layouts and components are project-owned. Keep modules small. Put styles in `src/styles/` so Stylelint checks every authored style.
- Register MDX components in `src/components.ts` and update `markdown.componentMap` in `astro.config.ts` together. Preserve visible Aside/ApiTable captions, Tab labels, Step headings, children, tables, code and LinkCard destinations in readable Markdown/AI exports; raw MDX retains component markup. Add new informative component contracts to `scripts/check-site.mjs`. Keep code examples available without JavaScript and avoid hiding page content until enhancement runs.
- Set the canonical `site` URL and project title in `astro.config.ts` before deployment. Static output is `dist/` and can be hosted anywhere.
- Use the root-declared package manager through `corepack pnpm`. Build public packages from the root before API verification, then run this workspace's `build`, `lint`, `typecheck`, `check:api`, `check:site` and `test`. `typecheck` combines Astro diagnostics with TypeScript checks. `check:api` reads generated public declarations and requires bilingual export/member sections. `check:site` invokes it before checking rendered source routes, navigation, edit links, metadata, links/anchors and Markdown/AI content. Search uses the production Pagefind index; verify it with `preview` after building.
- `lint:docs` builds before running Nimbus authoring lint, because its resolved rules and route manifest are generated under `.nimbus/`. Keep this preparation in the script so fresh checkouts do not depend on local caches.
- Verify `/llms.txt`, `/zh/llms.txt`, section indexes such as `/api/llms.txt` and `/recipes/llms.txt`, `/llms-full.txt`, and each page's `/index.md` and `/index.mdx`. Manual API anchors must survive HTML, Markdown and MDX exports. Keep private content outside public content collections; `noindex` is not access control.
- Static checks do not replace interaction acceptance. Verify desktop/mobile layout, search/shortcuts, focus, copy buttons, theme selection/persistence, language switching and no-JavaScript content in a production preview. Preserve dates and partial/pending states in framework/IDE validation records; compiler support does not prove every browser CSS feature works in WXSS.
- `draft: true` excludes unfinished pages from production. When adding a page, create its translation before publishing so the language switch remains valid.
- Keep `nimbus.json` and `UPSTREAM.md` when upgrading. Review Nimbus migrations and project-owned changes before advancing the reviewed version.
